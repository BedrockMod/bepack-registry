# 收录指南

## 需求

作者首次通过 PR 登记其来源，后续版本无需手写发布索引。

## 架构

参考 `examples/source.json` 在 sources/<pack-id>.json 登记。示例中的 OWNER、REPOSITORY、ID 0 和全零提交必须替换为实际值，不能直接提交收录。
作者仓库根目录放置 `.bepack-registry.json`，内容参考 examples/repository-proof.json；proof.commit 指向默认分支可达、确实包含证明文件的提交。
仓库数字 ID 是身份依据，URL 名称仅用于展示和访问。首次命名权、来源迁移和解除隔离须人工审核。
收录不得运行作者脚本；不得以作者提供的扫描报告替代服务端独立复核。

## 备注

2026-11-08 已实现本地验证器、来源 proof、不可变记录、catalog、四个工作流和签名通知桥；远程 Apps/Secrets/HTTPS/catalog 服务尚未部署，不能宣称已经上线。示例不在 sources 中，当前无真实登记。

来源数据 PR 不得混入 lib/scripts/schema/workflow/依赖变更。必需门禁应同时包括 `registry-check` 离线测试和 `registry-verify` 可信 base 联网检查；后者只读取候选 Git blob，绝不检出或执行 PR 代码。首次来源审核 proof；登记后 sync 独立复验五资产与扫描结果生成版本 PR，新增版本由可信门禁再复验后才允许发布。来源 PR 合并不等于包已收录。

作者发布 `v<SemVer>` 的公开 Release，五资产为 `.bepack`、对应 `.sha256`、`bepack.json`、`bepack-release.json`、`scan-report.json`，必须已上传完成，Tag/仓库/锁与实际字节一致。安装只读 Notifier App 可实时通知；未安装时由每6小时同步补偿。作者不持有官方写 token 或任何 App 私钥。真实扫描许可/配额及生产账户端到端、App/桥/catalog部署仍须验收；详见 [索引服务模块](../../../docs/bepack-索引服务模块.md) 和 [通知桥](../bridge/README.md)。
