# 运维与撤回

## 需求

保证版本身份不可变、失败可恢复、已收录内容出现安全问题时可隔离。

## 架构

同包同版本 Tag commit、资产 ID 或摘要变化时隔离，不替换原记录。新版本扫描服务异常保持待处理，不把异常当零检出。
状态为 active、yanked、quarantined、unavailable；解除覆盖需人工复核，删除撤回文件不构成恢复。
索引采用内容寻址详情与原子入口更新；生成失败保留上一完整快照。
通知只提供抓取线索，真实仓库、Release、Tag 和资产均重新通过 API 验证。

## 备注

2026-11-08 已实现通知桥、6小时补偿、Bot PR 和 catalog 发布工作流代码，33项受控单测通过；真实 Apps、Secrets、HTTPS 主机、catalog分支与生产账户扫描尚未部署/验收，不表示服务已经上线。

网络/配额/配置/扫描未完成记 pending，不写零检出；明确恶意/可疑或既有版本验证失败记 quarantined。删除 Release 只标 unavailable，不降低既有 quarantined/yanked。普通重新抓取成功不自动解除撤回。`enabled=false` 暂停同步并抑制该来源 latest，历史记录仍保留。

撤回在 `withdrawals/<pack-id>/<version>.json` 写 schema_version/pack_id/version/state/reason/created_at/advisory_url；原因须可审计，解除覆盖使用人工复核的 active 状态记录，不删除文件或改原 Release 摘要。安全状态 PR 需维护者人工批准，不设置为普通新版本自动合并。发布全局串行、保留旧 packs详情；生成或非force push冲突失败应重跑，禁止强推覆盖。

桥仅单副本持久卷；恢复备份先停实例，恢复后运行全量 sync补偿。监控 pending积压、dispatch失败、最近一次6小时任务、catalog发布时间与磁盘占用；`/healthz`不证明外部API正常。详见 [通知桥部署](../bridge/README.md) 和 [索引服务模块](../../../docs/bepack-索引服务模块.md)。
